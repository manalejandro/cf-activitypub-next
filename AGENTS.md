# This is NOT the Next.js toolchain you know

The app runs on **vinext** (Cloudflare's reimplementation of the Next.js API on Vite), not on the Next.js compiler: `vite dev` / `vite build` / `vinext-cloudflare deploy` replace `next dev` / `next build` / OpenNext, and the app executes inside workerd in dev and production. Keep using the Next.js 16 public API (`next/*` imports, App Router conventions), but read `npx vinext check` / https://vinext.dev/docs/reference/differences before assuming an internal or a newer experimental feature behaves like Next.js.

# CF ActivityPub — Agent Instructions

A Mastodon-compatible ActivityPub server running entirely on Cloudflare Workers (Next.js 16 App Router on vinext + @vinext/cloudflare). No Node.js server, no Docker, no database server — everything is a Cloudflare binding. This file is the working contract for anyone (human or AI) changing this repo.

## Ground rules

- **Next.js 16 public API on vinext.** Route handlers receive `{ params }` as a `Promise` and must `await` it. `npx vinext check` / the vinext docs are the source of truth for what is implemented; don't assume internals or experimental features behave like Next.js.
- **No `next` dependency**: `next/*` resolves to vinext's shims at build time (`vinext/dist/shims/public-shim-map.json`); types come from `vinext/types` via the generated `next-env.d.ts` (never edit it by hand). Tests apply the same mapping (`NEXT_SHIMS` in `vitest.config.mts`) — a new `next/*` import must be added there or tests fail to resolve it. `eslint.config.mjs` inlines the old `eslint-config-next` rules (that package needs the Next compiler).
- **`src/worker.ts` is excluded from the main tsconfig** — validate it with `npx tsc -p tsconfig.worker.json --noEmit`.
- **Workers runtime**: no Node-only globals (stay portable even with `nodejs_compat`). Bindings via `import { env } from "cloudflare:workers"` — never `process.env`.
- **No secrets in git.** `wrangler.toml` holds public vars/bindings/resource IDs; secrets go through `wrangler secret put`. `.env.example` is the reference of every variable and its default: copy to `.env` to change dev **and deploy** — the `dotenvIntoWorkerVars` plugin (`vite.config.ts`, a `buildApp` post-hook) merges `.env` into `dist/server/wrangler.json` after the build and **fails the build** if the config is missing or `INSTANCE_URL` is absent/localhost (the Cloudflare Vite plugin only fills names wrangler.toml's `[vars]` lacks, and wrangler.toml has no `[vars]`, so a skipped merge would deploy a worker federating as `http://localhost:3000`). **`.dev.vars` is DEV-only**: neither `loadDotenv` (which the build merge uses) nor `wrangler versions upload` reads it, so a value only there never reaches the deployed worker. Secrets are never copied (`*_SECRET`/`*_TOKEN`/`*_PRIVATE_KEY`/`*_API_KEY`/`*_PASSWORD`/`CALLS_TURN_KEY_ID` are skipped with a warning). `npm run check:env` keeps the reference complete.
- **Validate before finishing**: `npx tsc --noEmit && npx tsc -p tsconfig.worker.json --noEmit && npx eslint . && npx vitest run && npm run check:env && npm run check:openapi`. After adding/removing routes or touching `vite.config.ts`/`wrangler.toml`/`src/worker.ts`, also `npx vite build`.
- **API docs**: `npm run generate:openapi` (runs on predev/prebuild/prepreview/predeploy); `npm run check:openapi` fails on a stale committed spec. The generator scans `app/**/route.ts` (paths/methods/tags/query params/bodies/leading comment), infers security from the handlers (admin paths and any handler that resolves the caller and rejects a missing one are locked; delegating/re-exported handlers inherit the target's guard; login/registration/public timelines/signed inboxes stay public), and builds response schemas from the TypeScript types (`lib/types/index.ts` + serializer return types). It reads the **raw source, comments included**: don't write an `if (!actor) … unauthorized()` shape literally in a comment. `lib/__tests__/openapi.test.ts` pins it.

## Data layer (D1 / SQLite)

- **`lib/db/schema.sql` is the single source of truth.** `scripts/upgrade-schema.mjs` replays its `CREATE TABLE/INDEX/TRIGGER IF NOT EXISTS`; still document each change with a numbered `scripts/NNN-*.sql` and update `lib/db/drop.sql` (children before parents).
- **Measure before optimizing**: `EXPLAIN QUERY PLAN` against the remote DB; confirm the index is used and rows drop. `USE TEMP B-TREE FOR ORDER BY` over tens of thousands of rows is the usual smell.
- SQLite/D1 does **not** use expression indexes for `ORDER BY`; partial indexes with `IN (...)` predicates are not matched by the planner.
- **`col IN (...)` on the leading index column defeats ordered scans**: split into one `UNION ALL` branch per value (each gets its own ordered index scan) and force with `INDEXED BY` when the planner still picks a range index. One case must keep the probe plan: `getHomeTimeline`'s follows branch (`idx_objects_actor_vis_pub`) — forcing an ordered scan destroys the zero-follows case, and every new local account starts there.
- **Home-timeline boosts** must drive from `announces` (`INDEXED BY idx_announces_created` + `CROSS JOIN`), else the planner reads the whole public table. Profile boosts use `idx_announces_actor_created`.
- **Cron scans must early-stop or be throttled**: aggregate in SQL (not JS loops over loaded rows); full-table sweeps run on KV-marker cadences; backfills drive `INDEXED BY` + `CROSS JOIN`.
- **Don't `ORDER BY` computed expressions over big tables** — denormalize and maintain on writes: `objects.engagement` (favs+boosts+replies, `idx_objects_trending`), `actors.last_status_at` (`idx_actors_discoverable_active`), `objects.has_link` (`idx_objects_actor_type_link`). Correlated per-row `MAX(published)` is a smell.
- **One date shape per column; `lib/dates.ts` is the only converter.** AP-derived columns (`objects.published`/`updated_at`, `announces.created_at`, `follows.created_at`) are **ISO 8601 with `Z`**; every other timestamp column keeps **`datetime('now')`'s shape** (`YYYY-MM-DD HH:MM:SS`, UTC) — with a documented set of operational columns whose writers bind `toISOString()` and are therefore ISO too: `instances.*_at` (**every** `INSERT INTO instances` must bind `last_seen_at` — the DEFAULT is DB-shape), `polls.expires_at`, `collection_items.created_at`, `actors.suspended_at`/`last_active_at`, `actor_fields.verified_at`, `push_subscriptions.present_until`, `oauth_tokens.expires_at`, `custom_filters.expires_at`, `mls_messages.published`. SQL comparisons against an ISO column use `strftime('%Y-%m-%dT%H:%M:%fZ','now',…)` or a bound ISO cutoff — **never `datetime('now',…)`** (`'T' > ' '` stretches any window by up to a day); `backfill:dates_normalized(_v2)` in the upgrade script heal legacy mixed rows. Mixing shapes silently breaks ordering/comparisons (space sorts before `T`). Boundaries: `toIsoOrNull`/`isoTimestamp` (never hand a stored shape to a client/peer), `parseDbDate` (browser), `dbTimestamp` (write a JS date). A Z-less ISO is read as *local* by JS — the helpers add the zone; never compare normalized ISO strings that disagree on milliseconds (re-serialize through `toISOString()`).
- **Future-dated federation content is stored but hidden until due** (skewed remote clocks pin posts to the top of timelines): timeline/profile/ranking readers carry `notInFutureSql()` (`published <= strftime('%Y-%m-%dT%H:%M:%fZ','now')` — same shape as the ISO columns, so it stays string-ordered and rides the published indexes as a range); `createObject` won't advance `actors.last_status_at` with a future date; live broadcasts are suppressed with `isPublishedInFuture`. Direct fetches by id (`/objects/:id`, `GET /api/v1/statuses/:id`) still serve it.
- **A timeline page must never make a round trip per status**: batch every lookup (`getActorsByIds`, `getDomainCallsSupportMap`, `getActorFieldsMap`, one `IN (…)` per concern) and never call a batch helper inside a per-status `.map()` (O(N²)).
- **D1 bind limit ≈ 100**: pass a JSON array and use `json_each(?)` for long `IN` lists.
- **List timelines**: prefilter the member set (minus blocks) and run one ordered scan per visibility (`UNION ALL` + `INDEXED BY`). Never join `list_accounts` with `visibility IN (...)` + correlated `NOT EXISTS`.
- **Suggestions** (`getAccountSuggestions`): pools fill in order (friends-of-friends → local → most-followed → fediverse-popular → active local), with a new-instances pool interleaved every 5th slot; seeded from the cron's follow recommendations (`lib/follow-recommendations.ts`, KV `suggestions:follow_recommendations`); pools rotate daily within windows of 5 ranks (`rotateSuggestionWindows`); suspended-instance domains are excluded from every pool.
- **Large backfills must be batched** (single full-table `UPDATE`s hit `SQLITE_NOMEM`): id cursor + byte-chunked statements in `upgrade-schema.mjs`; guard one-shot migrations with `instance_settings` markers.
- **Federated-history retention is opt-in** (`lib/storage-retention.ts`, cron stage `storage-retention`; `DB_RETENTION_DAYS` / `DB_RETENTION_MAX_BYTES`, both 0/off by default; `DB_RETENTION_PRUNE_BATCH`/`_SIZE_BATCH` bound each tick). Never pruned: local posts, DMs, followers-only remote posts, bookmarked/replied-to remote posts, accounts/follows/reports/moderation log. Deletion cascades like an origin delete; a pruned reply releases its parent's counters via one CTE `UPDATE`; `actors.statuses_count` is untouched (it is what the origin advertises). Batch selects are `UNION ALL` per visibility with `INDEXED BY idx_objects_vis_published`; the `NOT EXISTS` guards are covering-index probes. **The payload estimate is a sample, never an exhaustive walk** (jittered rowid probes × an index-only row count; exact rows, bytes within a few percent). The row count is itself a walk of every prunable entry (~400k / 1.2 s per call on cf-ap), so it is retaken at most once a day (`COUNT_REFRESH_HOURS`, `countIsStale`) and carried over between measures, decremented by what each pass prunes; the `activities` count is forced onto `idx_activities_published` so it stays index-only. The size budget compares `meta.size_after` minus what retention already freed (`nextFreedBytes`; SQLite reuses pages before shrinking), falling back to the sample. Admin: `GET/POST /api/v1/admin/storage` (manual pass audited as `storage_pruned`).
- **Never `DROP` stateful tables in the upgrade script.** Wrap queries in `try/catch` with a migration pointer when columns may be missing on old DBs.
- Reuse `lib/db/index.ts` shared SQL/helpers (`PUBLIC_STATUS_TYPE_SQL`, `notInFutureSql`, `isAcceptedFollower`, `countActorPublicStatuses`, `deleteRemoteActorData`); never inline type lists or fire ownership-less deletes.

## Federation rules

- **All outbound delivery goes through the queue** (`enqueueDeliveries`; fan-outs >100 chunked by count *and* bytes; only a persistently failing chunk falls back to direct delivery). `deliverToInbox` is reachable only from `lib/activitypub/queue.ts` and the worker consumer — never from a handler (the audit is mechanical: `postToInboxSigned`, the only signed inbox POST, has exactly those two callers). The DLQ records failures in KV (`dlq:delivery:*`, 30 days) and acks. **The consumer signs at delivery time** (`resolveDeliverySigningKey`): account deletion must park the key in KV (`actor:key:<actorId>`, 24 h, `deleteLocalAccount`) **before** the actor row goes; the row always wins over a stale grace entry.
- **Inbound signatures**: `verifySignature` requires `(request-target)` and, with a body, `digest` inside the signed headers; a valid `Date` (12 h window); RSA/hs2019 only. **Refresh throttles per actor, not per keyId** (`sig:refresh-actor:<actorId>`): the fragment is attacker-chosen and a per-key marker alone allows outbound-fetch amplification against a victim host.
- **Inbound bodies are bounded while streaming, never after buffering**: inboxes gate on `Content-Length` then read through `readBoundedBytes` before `JSON.parse`; outbound remote documents use `readBoundedJson`/`readBoundedText`; `proxy.ts` rejects non-multipart mutations over 2 MB by declared length.
- **Actor trust**: never cache a fetched actor document whose `id` differs from the fetched URL — `upsertRemoteActor(db, doc, expectedId)` at every fetch site. **Inline actor documents embedded in an activity are never cached** (`handleCreate`, `handleFlag`): relays legitimately forward third-party content signed with their own key, so an embedded `publicKey` is attacker-controlled — only the document served at the actor's own URL counts. `upsertRemoteActor` never updates `is_local = 1` rows (cache-poisoning guard).
- **Object attribution**: remote objects are stored only when `attributedTo` shares the object IRI's host and is not local (`handleCreate`, `handleLike`, `handleFlag`, `fetchAndCacheRemoteStatus`, `persistRemoteNote`). `persistRemoteNote` **requires** `attributedTo` (an unattributed embedded note would be stored under the announcer — IRI squatting), refuses authors on our own domain, and refreshes an already-stored object **only when the activity signer is that object's author** (a third-party boost carries attacker-controlled embedded data; a media-only post with empty content is an easy forgery target).
- **Visibility**: every route reading an object by id gates with `canViewStatus(obj, viewerId, isAcceptedFollower(db, viewerId, obj.actorId))` — including source/history/translate/favourited_by/reblogged_by/pin/account statuses and the AP endpoint **`GET /objects/:id`** (anonymous: public/unlisted only; only those are KV-cached). `getFollow` ignores state — never use it for visibility. Followers-only is visible to the author, accepted followers **and mentioned accounts** (Mastodon `StatusPolicy#show?`). **Boosted originals are judged against their own author, never the booster** (`boostedOriginalVisibilitySql` in `getActorBoosts`/`getActorStatuses`); inbound `handleAnnounce` drops announces of `direct` objects and of `private` objects announced by anyone but their author.
- **Domain blocks** (`instance_domain_blocks`): `suspend` drops the activity; `silence` processes it but strips media (`reject_media`) and ignores forwarded Flags (`reject_reports`).
- **Inbound reports (Flag)**: one `reports` row per target, then the same Guardian pipeline as local reports. A remote report only arrives when the reporter ticked "Forward to" at the origin (Mastodon) — an empty table is not a bug. Outbound: a local report of a remote account with `forward: true` sends `Flag{object:[target,…statusUris]}` to its inbox (`buildFlag` via the queue; `reports.forwarded`). **The origin's decision comes back through the actor document** (`toot:suspended` → `applyRemoteSuspension`, `suspension_origin='remote'`; a `'local'` suspension is never overridden; the inbox's `Update{Actor}` broadcasts `account.updated`). **Evidence stays visible**: a suspension nulls content, so the admin report view recovers text/attachments from the stored AP document. Local targets get a moderation notification **from the Guardian** (never the reporter) and at most one email/day.
- **Unreachable/blocking instances**: the consumer records failures in `delivery_rejections` (permanent 400/401/403/404/410/422; `status = 0` for network/5xx with the real status in `last_error`) behind a per-host KV throttle (`delivery:failrec:<domain>`, 10 min — a dead host burns 16 retries per queued message and every attempt used to rewrite two D1 rows); a later success sets `last_ok_at` (staleness-gated to one write per 10 min). `/api/v1/graph` exposes 403 as `blockedBy` and 0 as `unreachable` (while `last_ok_at IS NULL OR last_at > last_ok_at`). Circuit breaker: 3 consecutive failures (1 h) — the success path resets the KV counter only when it exists (unconditional deletes were pure write quota).
- **Dedup**: `processInboxActivity` records each signed `activity.id` in `activities` (`INSERT OR IGNORE`) — only after signature/ownership checks. An **http(s)** id must live on its actor's or the signer's host (anti-squatting); `urn:`/`tag:` ids have no host to bind and dedupe by id alone (dropping them would reject legal activities with a 202 nobody retries). A handler failure rolls its dedup row back **and re-throws**, so both inbox routes answer 500 and the sender redelivers (a 202 marks the delivery successful forever).
- **Boosts (Announce)**: the `announces` join table stores each boost; `createAnnounce` persists the caller's `createdAt` (it drives ordering) and bumps counters. Timelines surface boosts: home unions own/followed posts with boosts (ordered by announce time; a followers-only original only shows when the viewer follows its author; suspended/blocked boosters and blocked domains filtered); profiles include boosts by default (`exclude_reblogs=true` off) and the Boosts tab is `only_reblogs=true`. Both return `TimelineEntry[]` serialized with `serializeReblog` (wrapper ids are announce ids; cursors resolve via `resolveTimelineSortCursor`).
- **Ownership**: embedded objects in Announce/Update must be authored by the signer or share origin; MLS mutations are actor-scoped; call events validate against the `call:<id>` KV session.
- **Custom emojis**: every outbound AP document carries the **source** text (`:shortcode:`) plus the `tag` Emoji array (actor and notes: content, summary, contentMap) — Mastodon's sanitizer has no `img` and only replaces shortcodes. Stored content and the REST API keep the rendered `<img>` with Mastodon's markup; `emojiImgsToShortcodes` converts at build time; the Emoji tag declares the real `mediaType`. `serializeStatus` re-renders from the catalogue, falling back to the object's AP `tag` (`emojisFromRaw`) — without it a just-published reply keeps `:shortcode:` as text. Account notes render the same way: **every route returning accounts whose bio the client shows passes `getAllCustomEmojis(env.DB)`**.
- **Mentions carry the actor IRI**: canonicalize Mention tags before building the Note (`canonicalizeMentionTags`; cached actors offline, unknown via `fetchAndCacheRemoteActor` with id-binding). A `/@user` href makes peers skip the mention notification and the delivery. Inbound is lenient the other way (`resolveLocalMentionedActor`). **Only mentions that resolve to an account render as links** (`MentionsMap`): create/edit/admin composers build it with `resolveMentionLinks` before rendering; `serializeStatus` derives it from the stored AP `tag` (`mentionLinksFromRaw`).
- **Polls**: a vote arrives as `Update{Question}` with the same body — refresh counts (`refreshPollFromQuestion`) **without** `updateObject` (it would stamp `updated_at` and mark the status "edited"); the refresh **skips the write when the counts did not change** (the 3-min cron re-reads every live remote poll — identical documents must not rewrite the option rows). `ensurePollRowsForQuestion` creates rows **and applies counts**, also on object reuse and re-announce. Every serialization that can show a poll loads it (boosts, quotes).
- **Documents (PDF/plain text)**: `DOCUMENT_MIME_TYPES` with `MAX_DOCUMENT_SIZE` (32 MB). Stored/serialized as `unknown` (Mastodon has no `document` type; clients render a download link); over AP as `Document` + real `mediaType` (`toAPAttachment`, shared helper). Inbound `apAttachmentType` maps document MIME types to `unknown` — **never `image`**; `application/octet-stream` keeps the old path. `mediaLimitFor` is the single per-type cap (routes **and** client). They open in `DocumentViewer` (PDF framed; text via `readCappedText`: Range + 256 KB cap, rendered as text); `documentPreviewUrl` rewrites own `/api/media/...` URLs to relative (CSP, framable, real `download`). Profile media galleries skip documents. **PDFs get their metadata stripped like every other medium** (`lib/media/strip-pdf.ts`, wired through `metadataStripKind`/`stripMetadataBytes` — both the upload path `putMediaObject` and the federated media cache): the document is REBUILT as a single fresh revision (xref chain walked, ObjStm/xref streams expanded, new xref table + trailer + random `/ID`) without `/Info`, the XMP `/Metadata` stream, the revision history or the old file ID — an appended "clean" revision is not enough, the history stays carveable. Length changes, so `metadataStripBuffers("pdf")` forces the buffered path in the cache downloader. **Fail-open contract**: encrypted (`/Encrypt`) or not-exactly-parseable files are stored UNCHANGED with a `[strip-pdf]` warning naming the reason — a damaged rewrite of somebody's document is worse than metadata we could not remove.
- **Poll statuses are always served as Questions** (`applyPollToNote`): object endpoint, outbox, edit `Update`, create `Create` — Mastodon re-fetches the URL to refresh counts. Any new local AP path must apply it.
- **Events**: the composer publishes an AS `Event` (`parseEventInput`, `lib/event.ts`); `buildNote` switches type and adds `name`/`startTime`/`endTime`; venue and geolocation merge into one `Place`; the `type` column says `Event`; the scheduled-publish cron and the edit route carry the event (`eventFromRaw`). A local event shows no "open original" link.
- **Quote authorizations (FEP-044f)**: a quote is only visible on Mastodon 4.4+ with a `quoteAuthorization` issued by the **quoted** post's server. `lib/activitypub/quotes.ts`: a local quote of a local post mints it on the spot (served at `/quote_authorizations/<id>` as a real document — never a fragment IRI); quoting a remote post sends `QuoteRequest`, and the `Accept.result` is validated (https + quoted account's host + our status) and stored with `setObjectQuoteAuthorizationUri` (**not** `updateObject`), then redistributed as `Update` carrying `updated`. Inbound `QuoteRequest` → Accept (public/unlisted, no block) or Reject (private/direct). **A direct message never touches the quoted author**: no `Create` delivery to their server, no `QuoteRequest` (it carries the DM's IRI), no local `quote` notification (its payload embeds the full status) — the quoted author is a third party outside the audience (Mastodon #36688); both the immediate path and the cron guard on `visibility !== "direct"`. The policy helpers (`quoteAllowed`/`remoteQuoteAllowed`) live in quotes.ts and run at compose time **and** again at scheduled-publish time. **An `Update` that changes nothing must not mark the status edited** (`handleUpdate` mirrors `ProcessStatusUpdateService`: `edited_at` only moves for real text/CW/media/poll/quote changes; otherwise `refreshObjectRaw` + authorization refresh). **The quote must persist on every path**: the Update branch writes `quote_id` (`setObjectQuoteId`); `updateObject` accepts `quoteId`; `ensureQuotedObjectCached` fetches an unseen quoted post; `repairMissingQuotedObjects` (cron `quotes`) and `backfill:object_quote_ids` heal old rows.
- **Outbound activity shapes follow Mastodon's serializers** (`lib/activitypub/utils.ts`): `Undo` mirrors the wrapped activity's `to`/`cc`; `Follow`/`Accept`/`Reject`/`Move`/`Like` carry **no** audience (recipients are the delivery target); relay `Follow`/`Undo` match `Relay#unfollow_activity`; `Move.object` is the **origin** account (destination in `target`); `Delete{Note}` wraps a Tombstone; `Delete{Actor}` sends the bare actor URI with id `<actor-uri>#delete`. Notes declare `interactionPolicy.canQuote.automaticApproval` (missing ⇒ denied on 4.4+), the `likes`/`shares` collections and the OStatus `conversation` for threads. Actors advertise `webfinger` and the profile settings. Every serialized property must be declared in the context (`lib/activitypub/vocab.ts`).
- **Featured items federate; account recommendations don't**: pin/featured-tag send Mastodon's `Add`/`Remove` (no `id`, no audience) through the queue (`deliverFeaturedChange`); `object` is the status IRI or a `Hashtag` document; `target` is `/users/:username/collections/featured` or `.../tags` — both must be served (they were advertised but 404'd). Account pins (`AccountPin`) stay local and require following the target; profiles read `endorsed`/`note` from the relationship.
- **Actor profile settings** (Mastodon ActorSerializer): `actors.memorial`/`show_featured`/`show_media`/`show_media_replies`/`attribution_domains` (run `scripts/upgrade-schema.mjs` before deploying — suggestion pools filter on `memorial`). Outbound: `buildActor` always sends the three toggles (default true), `memorial`/`suspended` only when set, `attributionDomains` only when non-empty; a suspended local actor still serves its actor document with `suspended: true` and suspension/unsuspension distributes it (`broadcastActorState`; `broadcastActorUpdate` must keep sending `suspended`/`memorial`). **A suspended account is disconnected locally**: web profile shows the notice without tabs, hides the follow button (an existing follow keeps its unfollow), message/call actions and the anonymous follow link — on both profile pages; `/api/v1/accounts/:id/statuses` returns nothing; **its notifications are not served** (`getNotifications`/`getUnreadNotificationCount` filter suspended senders per row; one arriving while suspended is stored but never delivered; `broadcastAccountUpdate` empties open notification lists); **nothing it wrote keeps being served** (`serializeAccount` returns instance defaults; `buildActor` omits icon/image/attachment) — only the handle survives; reinstatement restores everything. The status permalink of a suspended author is a 404 (except for the owner). Inbound: `upsertRemoteActor` stores the settings (`memorial`/domains **clear** when absent; toggles only update when the key is present — read the stored value first, a NULL bind aborts the upsert) and applies the document's `suspended` (`applyRemoteSuspension`). `normalizeAttributionDomains` mirrors Mastodon. REST: `serializeAccount` always exposes `show_*`, `memorial` when set, `source.attribution_domains` for the owner; `PATCH update_credentials` accepts them. Memorialize is full-admin (`accountActionGuard` with `removesAccess`), emails the owner, logs it; memorialized accounts cannot sign in and leave the suggestion pools.
- **Limited (silenced) accounts** (`actors.silenced`, admin → Limit): hidden from every public surface (timelines, trends, public streams, directory, suggestions, follow recommendations, oEmbed) while visible to followers (home) and on the profile; REST carries `limited: true`; federation unaffected; reversible. Two extra rules: a follow **from** a limited account becomes a follow request even on open accounts, and its notifications are **filtered** by default (`notifications.filtered = 1`: no stream/push/email; hidden from `/api/v1/notifications` unless `include_filtered=true`; out of the unread count; serialized with `filtered: true` — unless the recipient follows the sender). Limited accounts stay searchable and followable.
- **Status collections**: `likes`/`shares` (count-only) and `replies` (first page lists reply IRIs oldest-first: public/unlisted, `media_pending = 0`, `min_id` cursor) at `app/objects/[id]/[collection]/route.ts`; only local public/unlisted objects expose them. The outbox carries Mastodon's `last` link (`?page=true&min_id=0`), which resolves to the **oldest** page.
- **Profile feeds (RSS/Atom)**: `lib/feeds.ts` mirrors Mastodon — public+unlisted, no replies/boosts, newest first, `?limit=` (≤200), `?max_id=`; per item: CW preroll, rendered content with inline-sized emoji, poll options as disabled inputs, hashtags as categories, attachments as Media RSS + an `enclosure` for the first audio. Served at `/users/:username/rss|atom` (60 s cache) with `/@username.rss|atom` rewritten by `proxy.ts`; the profile advertises both (`<link rel="alternate">`). **Local accounts only**; a suspended account has none; a limited one keeps serving. **Every profile advertises feeds when the origin server serves them** (`discoverProfileFeeds`, `lib/feed-discovery.ts`): ours in Mastodon's public shape from `getBaseUrl(env)` (never the request Host); remote ones from a one-off probe cached in KV (hit: a week; miss: hours).
- **Markdown by content negotiation**: a client preferring `text/markdown` gets the document **built from our data** (the pages are client-rendered shells with no content in the HTML): `proxy.ts` rewrites `/statuses/:id`, `/users/:username`, `/@username` to `app/md/…` when `acceptsMarkdown` (q-values; a browser sending `text/html`/wildcard never gets markdown) and the routes answer `text/markdown; charset=utf-8` + `Vary: Accept` with the pages' visibility rules. `htmlToMarkdown` converts the tag set the sanitizer allows (emoji→shortcodes, shortened links→bare URL, script/style dropped). Deterministic, synchronous, no AI.
- **`Delete` cleanup**: `deleteObject` (notifications, conversation pointer, parent `replies_count`/`engagement`) and `deleteRemoteActorData` (`Delete{Actor}` purge). `Undo{Accept}` removes followers; `Undo{Follow}` only decrements accepted follows. A `Delete` whose signer key can't be fetched (`no-key`) is acked 202 when neither signer nor target is cached (retrying those flooded the inbox with 5xx); anything cached still answers 503.
- **Profile moves (Move)**: outbound `lib/activitypub/migration.ts` (`/settings/migration` → `POST /api/v1/accounts/migrate`): WebFinger resolves the destination; the destination must list the source in `alsoKnownAs` (refreshed once before refusing); the source records `movedTo`; **every local follower is re-pointed and sent its own `Follow` signed by that follower** (the target instance only learns of followers from a Follow); counts adjust; the `Move` goes to remote followers **and the destination instance** through the queue (`delivered` counts servers). **Inbound `Move` follows Mastodon's shape**: `object` is the ORIGIN (must equal actor/signer) and `target` the destination; the legacy shape (destination in `object`, no `target`) is tolerated only when `object ≠ actor`; the destination's alias is the real anti-hijack gate. **Aliases** are the destination half (`/settings/migration` + `GET/POST/DELETE /api/v1/accounts/aliases`, `lib/activitypub/aliases.ts`): resolved against the local DB (never a self-fetch — a Worker fetching its own hostname times out, HTTP 522) or WebFinger + hardened fetch; stored in `actors.also_known_as`, served by `buildActor` and pushed to followers (`broadcastActorUpdate`). **A moved profile shows a banner, never an HTTP redirect**: REST carries `moved` (`getMovedAccount` — every profile-shaped route must fill it, `lookup` included), the actor document carries `movedTo`, the web profile hides the follow button unless already following, and the account leaves discovery (suggestions/search/directory filter `moved_to IS NULL`). Only followers move; posts/following don't.
- **Follows**: the follow route stores a remote follow optimistically as `accepted` (`pending` only with `manuallyApprovesFollowers`) and bumps `following_count`; `Reject{Follow}` flips the row to `rejected`, undoes the increment and broadcasts `relationship` on the local follower's `user` stream (`Accept{Follow}` does the same for a pending row). A rejected row reopens on a new inbound Follow. `remove_from_followers` sends `Reject{Follow}` (wrapping the original, `follows.activity_id`) to a removed **remote** follower's personal inbox. `deleteRemoteActorData` subtracts cascading follows from local counters before the purge.
- **Remote accounts require auth**: `/api/v1/accounts/:id` (401 anonymous remote), remote `lookup`, `:id/statuses`, `:id/collections`, `/users/remote`, `/api/v2/search` remote resolution, on-demand `statuses/:id`, `/api/v1/e2ee/resolve`. Local profiles stay public; discoverable collection pages stay public. `/api/v1/accounts/search` accepts a username prefix, display-name substring, handle with/without `@`, or a profile URL (`parseAccountQuery`); cached remote results stay auth-only; `resolve=true` fetches via WebFinger.
- **Remote handle URLs are link-outs**: `/@user@domain` rewrites to `/redirect?url=…` (interstitial); direct `/users/user@domain` redirects there too; same-instance handles stay local.
- **Outbox**: `buildOrderedCollectionPage`; `totalItems` counts only public statuses; the cursor advances with the last fetched status regardless of visibility; suspended actors 404. Collections are CORS-enabled via `proxy.ts`. AP collection `?page=` is capped (`MAX_AP_COLLECTION_PAGE`) and only well-known page shapes are cached (client-controlled values in cache keys are a KV write-quota flood; the outbox key includes `min_id`).
- **Collections (FEP-7aa9)**: local actors advertise `featuredCollections` and serve `/users/:username/collections` (+ `/collections/:id`, `/feature_authorizations/:itemId` for local item accounts); mutations enqueue `Update`/`Delete{FeaturedCollection}` to followers. Remote collections are cached by `syncRemoteCollections` (KV throttle 1 h; forced by inbound `Update{FeaturedCollection}`; removed by `Delete`); `collections.url` stores the remote web URL and `collectionHref()` picks the right link.
- **Scheduled statuses** publish through `createObject` + `enqueueDeliveries` + streaming and link pending media (`pending_media:` KV, TTL extended at schedule time) — don't hand-roll inserts; `publishDueScheduled` verifies the pending upload's owner (`pending.actorId`) before linking it. The cron mirrors the immediate path: encoded ids decoded (`decodeStatusId` for `in_reply_to_id`/`quoted_status_id`), the Guardian `screenStatus` gate (blocked → the row is dropped), FEP-044f quotes (local authorization minted on the spot, `QuoteRequest` for remote ones), thread participants addressed, DM conversations + block-filtered home streams, and no publishing for suspended/memorialized accounts (their rows are deleted). **Publish time revalidates what the schedule-edit route does not**: the quote policy (`quoteAllowed`/`remoteQuoteAllowed` + visibility — a disallowed quote is dropped, the post still publishes) and the reply target (`canViewStatus` — an unviewable parent drops the reply link instead of joining an invisible thread). The object id is **deterministic** (`scheduledNoteId`, sha256 of the schedule id in UUID shape), a retry reuses the **stored** `published` (the raw document never drifts from the column), and the row is deleted **last**, so a transient failure re-runs idempotently instead of duplicating or losing the federation. Orphan rows (missing actor or key) are deleted on sight so they cannot starve the due window. Scheduling is capped at 30 days (`SCHEDULE_MAX_HORIZON_MS`, the `pending_media:` TTL — `scheduled_error_horizon`).
- **Consume or cancel every outbound response body** (`discardBody`): unread bodies stall the runtime's in-flight fetch pool. R2 rejects streamed uploads without a known length — use `FixedLengthStream` and cancel the stream if `R2.put` fails.
- **SSRF**: `safeFetch` (or at least `validateOutboundUrl`) before every outbound request. `safeFetch` re-validates each redirect hop and bounds the exchange with a timeout (`timeoutMs <= 0` disables it for the audio relay); it blocks private/metadata/CGNAT/multicast ranges and internal suffixes; it returns `null` (never throws) on network failure.
- **Every outbound federation request carries a User-Agent** (`federationUserAgent`, set by `safeFetchTracked` when the caller sends none; the media cache's `fetchWithUserAgents` UAs are respected): Workers' `fetch` sends none and strict servers reject outright (GoToSocial answers 418 to everything).

### Federation engine (instances)

- `instances` registry (one row per remote domain: NodeInfo metadata + availability). `lib/activitypub/instances.ts` fetches `/.well-known/nodeinfo` (2.1→2.0→1.0, SSRF-guarded) with an `/api/v2/instance` fallback; the cron refreshes due instances (`INSTANCE_REFRESH_BATCH`/`_DAYS`) and expires dormant metadata daily (`INSTANCE_DORMANT_DAYS`, kept if a local account follows them). `/api/v1/instance/peers` reads the registry.
- **Availability** (Mastodon `DeliveryFailureTracker`): failures on 7 distinct UTC days mark a host `unavailable` + KV `inst:down:<domain>` (24 h; the queue consumer skips without a D1 read); any success clears it — including a **signed inbound activity** (`recordInstanceInboundActivity`, KV-throttled 6 h). `recordInstanceSuccess` runs on EVERY successful delivery and is **staleness-gated in SQL**: a clean row refreshes at most once an hour (the gate compares ISO shapes — `instances` timestamps are ISO-Z, never `datetime('now')`), a dirty row (failure state) clears immediately. That is the only recovery path for hosts we stopped delivering to.
- **Delivery target**: `collectFollowerInboxes` prefers `endpoints.sharedInbox` (`actors.shared_inbox`); the backfill cron drives from `follows` (`INDEXED BY idx_follows_target` + `CROSS JOIN`), failures parked in KV 7 days. Per-user inboxes time out on some implementations.
- **Retries**: `max_retries = 16`, delay `(attempts^4)+15+jitter` capped 24 h (`deliveryRetryDelay`), `Retry-After` honored for 429/503; permanent 4xx ack; exhausted → DLQ.
- **Admin**: `/admin/instances` + `/api/v1/admin/instances` (list/filter, add/refresh, reset availability, suspend/unsuspend, purge a domain's cached actors). Suspend sets KV `inst:paused:<domain>`; actions audit to `moderation_log` (`target_type='instance'`).

### Relays

- An admin adds a relay by its **inbox URL** (`/admin/relays`, `/api/v1/admin/relays`; states `idle|pending|accepted|rejected`). Enabling sends `Follow{object: as:Public}` signed by the reserved instance actor (`getInstanceSigner`) and parks the row in `pending`.
- `Accept`/`Reject{Follow}` are matched by `follow_activity_id` and only from the relay itself: `relayMatchesFollowAnswer` = `relayMatchesActor` (actor URI, inbox, or `endpoints.sharedInbox` — the shape `LocalActor` actually stores) plus a same-host fallback that is safe ONLY here because the unguessable `follow_activity_id` already proves who we asked. Content matching (Announce/forwards) stays strict (`relayMatchesActor`/`acceptedRelayForSigner`). `/admin/relays` polls while pending (5 s, skipped in background tabs). Disabling sends `Undo{Follow}`; removing unsubscribes first; every mutation is audited and needs a full admin (moderators read).
- An `Announce` from an accepted relay is stored as a **normal remote status, never a boost** (`storeRelayedStatus`): the object is taken embedded or fetched, attributed to its real author, and the **author's** domain block applies (the relay signed, not the author). An announce from a known-but-not-accepted relay is ignored. A status whose media is still caching stays held; an already-stored object is skipped.
- **Relays that forward original activities** (`activity-relay`, Mastodon relay mode) send third-party `Create`/`Update`/`Delete` **signed by the relay**: the anti-spoofing check allows that cross-actor case only for those content types, only while the subscription is `accepted`, never for local authors (`isAcceptedRelayForward`), judged by the author's instance block. They publish PKCS#1 keys (`BEGIN RSA PUBLIC KEY`): `security.ts` wraps them in SPKI (`publicKeyDer`/`pkcs1ToSpki`).
- **Outbound**: every local **public** status is also delivered to each accepted relay's inbox (`withRelayInboxes`/`acceptedRelayInboxes`) — creates, edits, deletes, scheduled publishes, auto-delete. Unlisted/private/direct never go to relays.

### Account expiration (inactivity)

- `lib/moderation/account-expiration.ts` (cron `expiration`, 5-min KV throttle). Enabled by default (`account_expiration_enabled` / `account_expiration_months` = 12, admin → Settings, months 1..120): email warnings **7 days** and **24 h** before, automatic suspension when the window passes (logged `suspended`, `model: "expiration"`), deletion **one month after the suspension**, whatever its origin, without further warnings.
- `last_active_at` is the clock: `getAuthenticatedActor` refreshes it (6 h throttle, gated in the UPDATE itself — a fresh actor costs zero written rows per request) and drops the warning markers (`expiry:warn:7|1:<actorId>`); `createActor` seeds it; the upgrade script backfills. Candidates walk `idx_actors_expiry`; the purge walks `idx_actors_suspended_at` (one branch per `is_local`). Administrators, moderators, the reserved instance actor and memorialized accounts are **exempt**. `suspended_at` is stamped with `COALESCE(suspended_at, ?)` (re-suspending never resets the purge clock); unsuspending clears it; the admin UI shows suspension and purge dates (`purgeDateFrom`). Suspended accounts are listed only in `/admin/suspended`.
- The purge covers **local accounts** (federated `Delete{Actor}` — parking the signing key in KV first; R2 uploads, `oauth_tokens`/`activities`/`moderation_log`, actor row + cascades) and **cached remote accounts** (`deleteRemoteActorData`). Both record a moderation entry.

### Licenses (FEP-6757)

- Catalogue in `licenses` (`/admin/licenses`, `/api/v1/admin/licenses`; public `/api/v1/licenses`). Canonical license URIs only. Seed (`seed:licenses`): six CC + CC0 + public-domain mark + "In copyright"; a removed entry is never re-created. The admin edits the **icon URL** and the **Fork Awesome badge keys** (space-separated, live preview); clients resolve icon → stored keys → known-URI badges → id letters (`licenseVisual`). Seed entries ship their keys (`seed:license_badges`, guarded by `badge_keys = ''` so admin edits win).

### Frontend page cache (Workers Cache API)

- `lib/page-cache.ts` (`withPageCache`, wired in `src/worker.ts` around `handler.fetch`): HTML shells are client-rendered and byte-identical with/without a session, but the framework served them `no-store`. The Cache API keeps them 60 s fresh (`PAGE_CACHE_TTL`, 0 disables) plus a 600 s stale-while-revalidate window serving the stored copy (`x-page-cache: STALE`, refreshed via `ctx.waitUntil`). The browser only ever sees `max-age=<ttl>`.
- **Cache API, not the CDN**: Cloudflare only honors `Vary: Accept-Encoding` and the framework sends `Vary: RSC, …` — the Cache API keys by URL *and* honors the stored `Vary` (HTML and RSC never mix) and normalizes the lookup request. Hashed static assets are already `immutable` via Workers Assets. vinext's own route cache (`x-vinext-cache`) serves some pages with a year-long `s-maxage`; this module bounds that and covers the `no-store` routes. `pageCacheLimitsFrom(resolveLimits(env))` is the typed bridge.
- Never cached: RSC/navigation fetches (`RSC`/`Next-Router-Prefetch`/`_rsc`), `/api/`, `/objects/`, `/inbox`, `/oauth/`, `/.well-known/`, `/quote_authorizations/`, `/feature_authorizations/`, requests with `Authorization`, non-GET, non-200, non-HTML, `Set-Cookie` responses, cookie-varying responses. `x-cf-ap-stored-at` is internal (stripped). Pinned by `test/page-cache.workers.test.ts`.

### Instance status and statistics

- `lib/instance-stats.ts` is the single source for the public page (`/status`, `GET /api/v1/status`) and the admin panel (`/admin/stats`, `GET /api/v1/admin/stats`) — they can never disagree (pinned by tests).
- Components: **web** (snapshot build time), **database** (`SELECT 1`; >`DB_SLOW_MS` degraded), **federation** (`MAX(activities.published)`, judged only while an accepted follow points at a remote account; >`FEDERATION_STALE_HOURS` degraded), **delivery** (`delivery_rejections` active rows + the `delivery:last_ok` marker written by the consumer, 2-min throttle; DLQ is the severe tail; **a handful of failing domains is not a fault** — state moves only for exhausted retries or a stalled delivery), **media** (disabled without cache; degraded above `MEDIA_OVERAGE_FACTOR`× budget — a full cache is the normal steady state — or `MEDIA_BACKLOG_FACTOR`× batch pending), **streaming** (a real fetch to the DO's `/health`), **maintenance** (`cron:last`, written in the cron's `finally`; <10 min OK, <60 degraded, older down, absent unknown). `summarizeOverall` reports the worst state without `unknown`/`disabled` dragging it.
- **No invented numbers** (no uptime %): every metric is self-measured; missing data says `unknown`. The public endpoint is KV-cached 60 s (`status:snapshot`) and answers `no-store`; the admin route computes per request. The page's refresh button sends `?fresh=1`, which recomputes behind a **global 15 s lock** (`status:fresh_lock`, epoch-ms value — KV TTLs floor at 60 s) so clicks can never turn into a count-recomputation flood. `/status` is public even with anonymous timelines closed. Both share `components/InstanceStatusPanel.tsx` and `lib/format.ts`.

### Remote media cache (R2)

- Federated resources are cached in R2 (`media_cache`, keys `cache/media/<sha256>.<ext>`) and served from `/api/media/...`; `attachments.remote_url` / `actors.avatar_url` keep the origin, the served `url`/`*_cache_url` point at the copy (serializers prefer the cache). Entries are keyed by source URL and applied to **every** reference; enqueueing an already-cached URL rewrites new references on the spot.
- **No blank posts while caching**: a fresh remote status is flagged `objects.media_pending = 1` and served/streamed immediately **with the origin URLs**; when its media lands in R2 (or permanently fails) the cron releases it (`releaseMediaPendingObjects`) and broadcasts an **update** (`status.update`; `mergeStatusUpdate` keeps viewer fields). Cards attach only when their image is cached/failed. `MEDIA_CACHE_MAX_HOLD_MINUTES` (30; 0 disables) releases older flags anyway; the flag clears when the cache is disabled. A released status whose publish instant has not arrived is **not** announced.
- Config (env; cache ON by default): `MEDIA_CACHE_ENABLED`, `MEDIA_CACHE_DAYS` (7), `MEDIA_CACHE_PROFILE_DAYS` (30 for followed profiles), `MEDIA_CACHE_MAX_BYTES` (10 GiB), `MEDIA_CACHE_MAX_OBJECT_BYTES` (40 MB), `MEDIA_CACHE_FETCH_BATCH` (20/tick), `MEDIA_CACHE_USER_AGENTS` (default: bot UA from `INSTANCE_VERSION`/`INSTANCE_URL` first, then browser UAs; non-media types, SVG and oversized bodies rejected).
- **Serving**: `/api/media/…` is intercepted in `src/worker.ts` **before** vinext (`lib/media/serve.ts`; the route is the fallback) — without the framework `Vary`, the CDN caches and answers video ranges at the edge. Ranges: single→206, unsatisfiable→416, **multi/malformed→200 whole body** (RFC 9110); HEAD/304/416 answer from `R2.head`; CORS allows `Range` and exposes `Content-Range`/`Accept-Ranges`. **Prefix allowlist** (`media/`, `cache/`, `emoji/`, `avatars/`, `headers/` — anything else 404) + `X-Content-Type-Options: nosniff` (the intercept runs before proxy.ts, so app security headers never reach it) + **per-prefix `Cache-Control`**: never-rewritten prefixes get 1-year `immutable`; mutable keys (`avatars/<username>.<ext>`) get 5 min + `must-revalidate` (a CDN copy of a deleted object cannot be purged).
- Hooks: `enqueueMediaCache` in `handleCreate`/`saveObjectAttachments`/`storeObjectAttachments`/remote featured items, and in `upsertRemoteActor` for avatars/headers **only when the URL is new or changed** (`enqueueNewProfileImages`). **Nothing may re-queue an evicted/expired URL** (re-download loop): `backfillMediaCache` only seeds followed profiles plus reference healing. Cron order: `maintainMediaCache` FIRST (expiry + eviction + orphan scan — the scan itself hourly), then the queue drain, the held-status release, and the optional backfill + the one-shot reference repair LAST (10-min throttle, rowid-window cursor in `instance_settings`).
- Expiry/eviction/purge **restore every reference before deleting** (`resetMediaCacheReferences`: `attachments.url = remote_url`, `actors.*_cache_url = NULL`, card snapshots back to the origin image) and match **by the cached URL as well as the origin** (a replaced avatar keeps its old copy until the new one lands). The apply/reset/repair paths dedupe `(object_id, url)` collisions before rewriting (unique index). A marker-guarded one-shot repair (`repairMediaCacheReferences`, `media_cache_refs_repaired`) forces `INDEXED BY`. Maintenance also drops entries whose owner is gone (a live account's avatar only goes with the actor row); the orphan sweep probes only indexed columns.
- Eviction runs **only over budget** and recycles **cold-and-quiet first** (`MEDIA_CACHE_COLD_DAYS` 3 without a serve, ≤`MEDIA_CACHE_COLD_MAX_HITS` 5 serves, `idx_media_cache_cold`), then least-served (`hits ASC, fetched_at ASC`, `idx_media_cache_evict`), 500 MB/tick, with `MEDIA_CACHE_MIN_ENTRIES` (20; 0 accepted) as a floor — only the full-admin purge wipes. `hits`/`hits_at` count **serves**: the hot path records in memory and flushes batched (300 s or 1000 keys, `lib/media/hits.ts` — the signal is statistical, a shorter window was one of the largest row-write sources on a media-serving instance); the counter restarts when an entry is served again after a window without serves (`mediaHitWindowDays`); `last_hit_at` slides the time-based expiry; only 200/206 count. Byte total is `SUM(media_cache.size)` in D1 (never KV). Downloads stream into R2 through a size-capped `TransformStream` with a bounded pool (8 concurrent) — buffering bodies exceeded the Worker memory limit; auto-delete is capped at 500 objects/tick. Fetching is a rolling window (only a >2× runaway overage pauses it); the queue is 70 % newest-first / 30 % oldest-first (pure newest-first starved the backlog). Admin: `GET/POST/DELETE /api/v1/admin/media_cache` (POST runs `enforceMediaCacheBudget`, 60 s cap; GET reports `top_served`). UI `/admin/media_cache` lists `top_served` as **plain links, never images or `next/link`** (rendering a preview counts as a serve and protects the entry); purge is full-admin and audited. `mediaCacheLimitsFrom(resolveLimits(env))` is the only bridge to the module (passing raw limits silently fell back to defaults).
- **Remote audio not currently cached** goes through the **same-origin relay** (`/api/media/remote`, `lib/media/remote-playback.ts`, per-IP rate limit): Web Audio silences cross-origin elements without CORS. It only serves URLs stored as audio attachments (indexed probe — not an open proxy), forwards `Range`/`If-Range`, disables the fetch timeout (episodes stream for minutes), 404s otherwise; the player **remounts** the element on the origin URL when the relay fails (`relayFailed`).

### Link previews (Mastodon PreviewCard)

- A status with a link queues its **first external URL** (hashtag/mention/own-instance links skipped) in `link_preview_queue`; the cron crawls it (`lib/link-preview.ts`). Statuses with media or a quote are skipped.
- The crawl tries **oEmbed first** (`rich` rejected), falling back to OpenGraph/Twitter Card/JSON-LD; `twitter:player` becomes a sanitized https-only `<iframe>` (scripts dropped). Outbound hops use `fetchWithUserAgents` + `safeFetch`.
- Cards live in `preview_cards`, keyed by the URL as posted, shared by every status linking to it, refreshed after `LINK_PREVIEW_DAYS`; unreachable/no-metadata URLs are negative-cached (`status='failed'`, 7 days). Env: `LINK_PREVIEW_ENABLED`, `LINK_PREVIEW_FETCH_BATCH`, `LINK_PREVIEW_DAYS`, `LINK_PREVIEW_MAX_BYTES` (`linkPreviewLimitsFrom` bridges).
- Each status stores a snapshot (`objects.card_id`/`card_json`) so `serializeStatus` emits `card` with no extra queries anywhere. Editing re-crawls only when the first link changed.
- When the card attaches, the cron broadcasts `status.update` (public channels, author's local followers' homes — author included — and lists containing the author, `broadcastStatusRefresh`); the merge preserves viewer fields; include the poll in the payload.
- **Every object-storing path queues the crawl** (`maybeEnqueueLinkPreview`): `persistRemoteNote`, the Update branch that creates a status, Like/Flag evidence caches, remote featured. `handleCreate` skips already-stored objects, so a status first cached elsewhere never gets a second chance.
- **YouTube** builds its card from the URL (`lib/youtube.ts`): `youTubeVideoId` (watch/youtu.be/shorts/embed/live/music; channels rejected) + `applyYouTubeFallback` (CDN thumbnail + nocookie player) even when the page 403s, via the direct oEmbed endpoint; placeholder titles dropped. **Instagram** likewise (`instagramShortcode`/`applyInstagramFallback`): no public oEmbed and a login wall from datacenters, so the public `/embed` player is always exposed as `embed_url` (`type: video`).
- The orphan sweep (`cleanupOrphanPreviewCards`, two-day window over `idx_preview_cards_created`) never deletes a live negative cache. **Cards are orphan-cleaned at write time by triggers on `objects`** (`objects_card_cleanup*`, `scripts/059`); `linkObjectPreviewCard` deletes the card of a status deleted mid-crawl.
- **Own status permalinks** are built from the database (a Worker fetching its own hostname times out, HTTP 522): author name as title, status text as description, the first **image attachment** as image (never the avatar), and the `/embed/<id>` iframe **only in `html`** (`embed_url` stays empty so the web UI never opens a status in the 16/9 lightbox).
- The web UI renders the card image (blurred while sensitive) + provider/title/description with `rel="nofollow noopener noreferrer"`. In-place playback via `playableCardEmbedUrl`: only provider **players** are framed (YouTube always, plus crawler-typed `video`); `rich` embeds are pages, not media — they keep the plain link card. `card.html` stays exposed for Mastodon clients.

## Security invariants (audited)

- **Registration**: always `email_verified = 0` + confirmation email (web and API); a Turnstile token must never auto-verify (API clients skip the captcha, not the email). API registrations get a Mastodon-shaped token that is unusable until confirmed. Local actor ids come from `getBaseUrl(env)`, never the request Host.
- **Canonical email (anti-abuse)**: `lib/canonical-email.ts` collapses `user+tag@domain` and dotted local parts for every domain; `actors.canonical_email_hash` + `canonical_email_blocks`; the flow rejects duplicates, auto-blocks after 3 attempts (24 h KV) and audits (`registration_blocked`). Admin API is full-admin.
- **OAuth**: codes require matching `client_id` + `redirect_uri` and PKCE whenever a challenge was issued; scopes are clamped to the app's registered scopes on every issuance path (empty scope ≠ full access); a session cookie is only set for same-origin logins. `/oauth/token` supports `authorization_code`, `password`, `client_credentials` (no actor, read-only, 1 h) and `refresh_token` (rotates in place, keeps refresh token and scope, re-checks the account). Only `client_credentials` leaves `actor_id` NULL. Crawler apps/app tokens are pruned (trigger + cron). **`/api/oauth/authorize` is a second credential surface** with the password grant's gates (the shared `login-fail:<hash>` lockout, suspended/memorial/unverified/pending rejection) **minus the captcha**: third-party apps open the consent page inside Android WebViews/Custom Tabs where Turnstile frequently cannot solve, so the widget and its server check live only on web login/registration/recovery (Mastodon's authorize has no captcha either); the consent route keeps its per-IP rate limit. `POST /api/v1/apps` is rate-limited 10/10 min per IP with `Retry-After` (clients retry registration per failed login, often behind a shared NAT — a tighter window locked real users out). The authorization code carries the app's **`client_id`** — the exchange compares that, never the internal `appId`. **Secret comparisons** (`ADMIN_TOKEN`, `client_secret`, PKCE, password hashes) go through `timingSafeEqualStr`.
- **Admin roles**: `requireFullAdmin` guards role changes, instance settings, federation rules, audit-log wipes, instance mutations; never demote/delete the last admin. Account actions go through `accountActionGuard` (reserved actor immutable, no self-actions, admin targets need a full admin, last-admin access can't be removed). **Deleting an account is full-admin** (moderators get 403 + `admin_account_delete_admin_only`). Privileged mutations write `moderation_log`.
- **The reserved instance actor (Guardian) is immutable**: `accountActionGuard` refuses every action (422 `admin_error_reserved_account`) and the moderation engine records `no_action` with `details.attempted`; patrol/registration/expiration sweeps exclude reserved rows. **Restorations stay possible** (`restores: true`). `ensureGuardianActor` self-heals the row.
- **Moderation notices**: `notifyAccountOwner` emails owners (local, with email on file) on warn/suspend/silence/remove, report rejection and status deletion; admin deletion calls it **before** the row disappears and records `emailSent`/`emailTo`.
- **A state change and its audit entry are one unit**: best-effort enrichment (vector learning, notice email, broadcasts) must each be non-fatal — `learnFromSuspension` never throws and the admin route wraps it before `recordModeration`; `recordModeration` reports failed writes to the console. `backfill:suspension_log_entries` reconstructs historical gaps (`model:'backfill'`, `details.backfilled`). Audit pages render timestamps with `parseDbDate`.
- **Guardian AI tiers (clef)**: first-line screening runs `clef-flash` per status (`screenContent`; categories ≥ 0.25 are reported and gate severity); reasoning decisions run the full `clef` through `decide()` (action from the choice question; confidence ≥ 0.7 high / ≥ 0.45 medium — suspension and registration auto-approval require high; `reason` via `signalsReason`). Clef has no system prompt: the policy lives in question instructions (`lib/moderation/prompts.ts`), evaluated data travels as a sanitized JSON state, and every question repeats that the state is untrusted content. A failed call retries once then returns null (heuristics take over); the chosen action is validated against the allowed set.
- **The Guardian is also a Cloudflare Agent** (`agents` + `@cloudflare/ai-chat`, `lib/guardian/`), grounded in its tools, never model memory. `GuardianAgentDO` is a DO (binding `GuardianAgent` + its own `new_sqlite_classes` migration — migrations are immutable once deployed), exported by `src/worker.ts` **and** `test/worker.ts`. `routeGuardianAgent` serves `/agents/guardian-agent/:instance` before vinext, gated to a **full administrator**. The tools (`lib/guardian/tools.ts`) are the only source of truth: reads + **`needsApproval` mutations** (the model proposes, a human approves; the approved action runs through the moderation engine with `model:"guardian-agent"` and is audited). Workers AI through the same `AI` binding; model id in agent state (default `@cf/zai-org/glm-4.7-flash`); it does not charge the automated Guardian's daily budget. **No decorator syntax may reach a bundle** (Oxc keeps decorators; workerd's V8 cannot parse them — a decorated agent took production down at startup): `exposeMethod` registers callables on the prototype and ESLint forbids `Decorator` repo-wide.
- **The Guardian learns from every suspension** (`lib/moderation/learn.ts`): `learnFromSuspension` embeds the offending content + a sample of the account's posts + its profile; **every** suspension path calls it (the engine before nulling content, the moderator route, the capped registration sweep). Human/rule suspensions store as confirmed decisions. Lifting is a correction: `forgetSuspension` deletes the vector. Lessons feed `vectorPreScreen` and sign-up (near-duplicate of a rejected registration → refused; looser match → precedent to the model). A domain block deliberately does not teach.
- **Every registration is audited**: one `registration_reviewed` entry with `details.verdict` (`allow`/`approve`/`reject`/`unreviewed`), the deterministic flags, the vector match and `pendingApproval` — whether the model reviewed or not. **The model's approve verdict changes no state** (never sets `email_verified`); a rejection deletes through `rejectAccount`, which also cleans `oauth_tokens`.
- **Captcha (Turnstile)**: `enforceTurnstilePolicy` requires a valid token on registration, web login and password recovery **whenever `TURNSTILE_SECRET` is set** (it skips only with no secret; a missing token is never "verified"). The OAuth consent form (`/api/oauth/authorize`) deliberately has **no** captcha — third-party apps open it inside WebViews where Turnstile frequently cannot solve (see the OAuth bullet). The password grant skips the captcha only for a registered app with matching `client_id`+`client_secret`. Failed passwords increment a per-account lockout (10/15 min, shared by both credential surfaces, checked **before** verifying, cleared on success). `expectedHostname` always from `getBaseUrl(env)`.
- **OAuth scopes**: `read` on GET/HEAD, `write` on mutations, `push` on push subscriptions; clamped on every issuance. Promotion moves one step (user → moderator → admin; promoting an admin is a no-op); role changes are logged; the reserved actor's role is immutable.
- **Streaming**: both DOs use the **WebSocket Hibernation API** (`acceptWebSocket` + `serializeAttachment` + tags + `webSocketMessage`/`Close`/`Error` + a storage alarm for the anonymous TTL); the 25 s browser keep-alive is answered by `setWebSocketAutoResponse("ping","pong")` in the constructor (waking on keep-alives defeats hibernation); `CallSignalingDO` implements `webSocketError`. List channels are owner-checked in the worker (dynamic re-subscribe limited to the socket's initial list); only public/unlisted statuses reach them; streaming tokens honor the REST gates. **`resolveToken` (WS) enforces the `read` scope and `memorial`** plus suspended/unverified/pending, with a versioned KV cache key (`ws_token:v2:`) so stale pre-gate entries are never served. **The home fan-out mirrors the REST filters**: `eligibleLocalRecipients` is the single gate. **A `direct` status is never pushed to followers' homes** — only the author and the addressed local recipients (block-filtered) receive it live, on both the create/edit routes and the scheduled-publish cron. Shared public/hashtag channels can't be per-viewer filtered: the web client fetches blocks + domain blocks once per session and `useNewStatusesBuffer` drops matching streamed statuses (caches invalidated on block/unblock).
- **Profile-field verification** is HTTPS-only and KV-throttled (silent skip for http; remotes retried ≤ every 6 h, re-verified after 30 days). An https field redirecting to http is blocked by `safeFetch` (expected log, not an attack). Our actor emits field values as `<a href="URL" rel="me">URL</a>` (`fieldValueForVerification`) — Mastodon only accepts an anchor whose `href` equals its text.
- **Browser-facing API errors**: stable `error_code` (i18n key) next to the English `error`/`error_description`; web forms translate via `translateKey`. Never ship untranslated user-facing strings.
- **Remote HTML** goes through `sanitizeFediverseHtml` (control chars stripped, http(s)-only media `src`); remote bodies are size-capped (2 MB) before parsing. The client `RichText` mirrors the whitelist and shares `decodeCodePoint` with the server sanitizer (a bare `String.fromCodePoint` throws a RangeError on `&#1114112;` and kills the render).
- **Federated URLs are validated before touching an attribute** (`lib/safe-url.ts`: `safeMediaUrl`/`safeHttpUrl`/`safeHttpsUrl`) — emoji `icon.url`, `attachment.url`, object `url`, Place pages. **Remote-document ingestion requires an absolute http(s) URL** (`safeHttpUrl` in `handleCreate`/`saveObjectAttachments`/`storeObjectAttachments`/`persistRemoteNote`/`Update{Actor}` icons): a relative URL from a peer would be served from our own origin and can never be media-cached. `safeMediaUrl` (which also accepts our own relative `/api/media/...` paths) is for rendering and local writes only. Both emoji renderers validate **and** `escapeHtml` (they concatenate *after* the sanitizer; an unescaped `"` in a federated emoji URL was stored XSS). Ingest validates too (`upsertCustomEmoji`, `createAttachment`); the instance's own emoji win shortcode collisions; `sameOriginRedirect` is the only way to resolve a `?redirect=` target (`/\evil.com` defeats any `startsWith("/")` shape check).
- **Pagination is clamped twice**: routes parse `limit` with `clampLimit` (SQLite reads a negative `LIMIT` as *no limit*; `?limit=-1` used to dump whole tables anonymously) and the `lib/db` readers re-normalize with `safeLimit`/`safeOffset` before binding.
- **Web Push is SSRF-guarded**: the subscription route validates `endpoint` (`validateOutboundUrl` — https only, no private/metadata ranges); delivery goes through `safeFetch`; a legacy non-https row is refused before any crypto work.
- **Rate limiting on abuse-sensitive surfaces is atomic** (`atomicRateLimit`, `lib/rate-limit.ts` → `RateLimitDO`): login, consent form, registration, uploads, WS upgrades, favourite/reblog/edit and the resolving search count in a Durable Object when `RATE_LIMIT` is bound, falling back to the KV counter otherwise (a KV get→put window is passable by a parallel burst). A limiter failure must never be the reason a login fails. Uploads also carry a storage quota (`UPLOAD_QUOTA_BYTES`, 5 GiB default, `getAccountMediaUsage`) and abandoned `media/…` keys are swept by the cron (`upload-orphans`: >31 days, unreferenced, not reserved by scheduled posts; cursor-bounded).
- **Passwords**: PBKDF2-SHA256 at 600k iterations (`PBKDF2_ITERATIONS`), stored as `pbkdf2:<iterations>:<salt>:<hash>`; legacy 3-part hashes (100k) still verify and are **transparently rehashed on a successful login** (`needsPasswordRehash`).
- **The session cookie is HttpOnly** (`setAuthCookie`): page JS can never read the web session. The client keeps a separate API-token copy in localStorage (`getToken`/`setToken`, `lib/client-api.ts`) for surfaces that cannot ride the cookie (WS query params — the worker's `extractToken` also reads the Cookie header); `SessionGuard` heals cookie-only sessions via `POST /api/auth/rotate` (same-origin only: SameSite=Lax), which retires the presented token and re-issues both halves. Logout/delete/revoke clear the cookie server-side and the localStorage copy client-side.
- **MLS PublicMessage envelopes**: the envelope `id` must share its author's host (no IRI squatting); a **remote** envelope is stored `unlisted` (third-party MLS traffic must not populate our public timeline); local ones stay public.

## Code conventions

- **Path alias** `@/*` → repo root. Always import with `@/`.
- **API routes**: exported async `GET`/`POST`/… typed `(request: NextRequest, { params }: { params: Promise<{ id: string }> })`. Use `json()`/`notFound()`/`unauthorized()`/`badRequest()` from `@/lib/cf`. Parse form-encoded bodies (Rails-built clients) with `formDataToBody`/`readRequestBody` (`lib/request-body.ts`) — they reproduce Rails' array/nesting conventions (`media_ids[]`, `poll[options][]`, `push[data][alerts][follow]`); a bare `media_ids=<id>` is accepted too (`normalizeMediaIds`). User-controlled arrays are capped (reports: 100 ids + `MAX_REPORT_NOTE_CHARS`; filters: `MAX_FILTER_KEYWORDS`; lists: `MAX_LIST_ACCOUNT_IDS` + `json_each`; scheduled media: `maxMediaAttachments`).
- **Streaming**: components never open a raw WebSocket — `lib/streaming/use-timeline-stream.ts` is a ref-counted shared manager (one socket per stream+params, kept 30 s past the last unmount); `user:notification` rides the `user` socket. Non-timeline events for one actor go through `broadcastEvent(ns, actorId, type, data)` — add an event type, never another helper. **Account state changes** (`account.updated`) go through `broadcastAccountUpdate` on public channels + the account's followers' homes + its lists (server queries hide suspended accounts, but cached clients keep rendering until the event — critical for **remote** accounts, which get no `Update{Actor}`); `handleStatusStreamEvent` drops everything the account authored (and boosts wrapping its posts) and clears those ids from `seenIds`. Admin tables waiting on a remote answer poll instead of using a socket.
- **Stream payloads and interaction responses are full statuses**: the client merge replaces everything except viewer fields (`favourited`…), so every `status.update`/boost payload **and every interaction response** (favourite, reblog, bookmark, pin, mute, edit, delete) must carry the full context (attachments, emojis, poll, quote, parent author) through `serializeStatusForStream` + `loadViewerStatusState`. A partial payload silently wipes what is on screen. Held (`media_pending`) statuses are never streamed; boosts fan out via `broadcastNewBoostToFollowers`.
- **Federated images render as plain `<img>`** (`images: { unoptimized: true }`): vinext routes `next/image` local paths through `/_next/image`, whose resolver only serves the static client bundle (every `/api/media/...` 404'd). `MediaGrid`/`LinkPreview` swap a failed image for a labelled placeholder (`media_unavailable`).
- **Search inputs**: debounce 400 ms, every run supersedes the previous one (`AbortController` + sequence guard), `try/finally` always clears the loading flag; clearing cancels the in-flight request.
- **Timelines**: feeds share `useTimelineCache` + `lib/streaming/timeline-cache.ts`. Always merge with `mergeTimelineItems` (dedup + newest-first by `created_at`); a failed/empty page never replaces cached items; `seenIds` derives from the visible items; `fetchPage` throws on `!res.ok`. **Every cache write goes through `setTimelineCache`** (cap `timelineCacheMaxItems`, default 1000). **Every feed-scoped state re-initializes when the key changes** (cursor re-read; `loadMore`/`catchUp`/`refresh` capture the key and drop a page that lands after a feed switch; `useNewStatusesBuffer` takes the key as `resetKey`). **Pagination follows a cursor, never the feed's last item** (`TimelineCacheEntry.cursor`, persisted): a catch-up merging an unseen page moves the cursor to that page's oldest; from the top the gap is filled eagerly up to `MAX_GAP_PAGES` (5); stop only on a page that makes no progress or an empty one; writes evict least-recently-written feeds beyond `TIMELINE_CACHE_MAX_ENTRIES` (12). **Streamed statuses go through `useNewStatusesBuffer`**: merged at the top, queued behind `NewStatusesPill` once scrolled away (pressing scrolls to top) — the feed never jumps under the finger; `delete`/`status.update` apply immediately; a background refetch defers too (`onDeferredItems` → `queueItems`: out of feed *and* cache). **Counters are never guessed client-side**: interaction handlers copy counts from the action's own route response; posting a reply re-reads the parent. **`StatusCard` is memoized**: handler props via `useCallback`, derived lists/composers wrapped in `useMemo`/`memo` — typing in a composer must never re-render the feed. **A server-filtered feed filters in the query, not the route** (notifications pass `types[]`/`exclude_types[]` to `getNotifications`, SQL-filtered via `idx_notif_target_created`; route-side filtering returned short pages and broke client pagination; each tab is its own cache entry; the stream refetch merges the first page with `catchUp`; reconcile on `visibilitychange`; the Mentions tab carries `direct`/`encrypted`).
- **Anonymous timeline access**: the `anonymous_timelines` setting (`public`/`public_local`/`none`; admin → Settings; `lib/anonymous-timelines.ts`) is enforced in the REST route (`/api/v1/timelines/public`, `local=true` included) **and** in streaming through one shared predicate, `anonymousStreamAllowed(channel, access)`: the worker applies it on every anonymous upgrade (the `?stream=` branches **and** the multiplex branch, whose default channel is `public`; hashtag streams are session-only like their REST route) and passes the level to the DO, which re-checks every dynamic `subscribe` (an anonymous socket cannot escalate). The UI reads it via `/api/v1/instance` (`useAnonymousTimelineAccess`); the admin PUT drops the cached instance payload. Any new anonymous surface must check it.
- **Auth**: `getAuthenticatedActor(request, env.DB)` from `@/lib/auth` (HttpOnly cookie or Bearer; client `getToken()` reads the localStorage copy — `SessionGuard` re-syncs it via `POST /api/auth/rotate`). It rejects suspended, email-unconfirmed and pending-approval accounts; mutations require `write`. Admin: `requireAdmin(request, env)` from `@/lib/admin-auth`. Suspended/deleted sessions bounce: `GET /api/auth/status` returns a `reason` and `SessionGuard` clears the token and lands on `/` — **no `reason` means "no session at all" and must never redirect** (anonymous visitors). Silenced accounts keep their session. The password grant rejects suspended/pending accounts with their `error_code`.
- **i18n**: 10 locale files in `lib/locales/`. `t` from `useLocale()` is a Proxy — use `t.some_key`; interpolate with `.replace("{var}", value)`. **Every key must exist in all 10 locales with identical key sets** — never hardcode user-facing strings.
- **Brand**: `useInstanceTitle()` / `INSTANCE_TITLE`; metadata via `generateMetadata()` (`app/layout.tsx`); the PWA manifest via `app/manifest.webmanifest/route.ts`. Don't hardcode the instance name.
- **Limits**: read `resolveLimits(env)` (`lib/constants.ts`); a new limit gets a constant and a line (with its default) in `.env.example` — `check:env` fails otherwise, and that file is both the reference and what `dotenvIntoWorkerVars` copies at build time. **Tests read limits from `resolveLimits(env)`; never hardcode env-dependent numbers in assertions.**
- **Avatar initials**: the fallback initial is the first **letter or digit** of the display name, then the username (`avatarInitial`, `lib/avatar.ts`), iterating code points (never cut a surrogate pair). Never `display_name[0]`.
- **Images**: custom loader in `next.config.ts`; prefer `next/image`. Non-square remote avatars need explicit `width`/`height` + inline `objectFit: "cover"` (Tailwind preflight overrides the attributes).
- **Fonts**: Wix Madefor Text (UI) + JetBrains Mono (code), self-hosted via `next/font/google` with `subsets: ["latin","latin-ext","cyrillic"]` (`ru` must not fall back to system-ui). Reference them via `--font-sans`/`--font-mono` (next/font hashes family names at build); never hardcode a family.
- **Remote content**: render via `renderRemoteContent`/helpers in `lib/activitypub/content.ts`; never inject raw remote HTML.
- **Objects**: set `updated_at = published` explicitly on insert (the column DEFAULT has a different shape and would mark new posts as edited).
- **ActivityStreams timestamps are ISO-8601** (`isoTimestamp`, defined in `lib/dates.ts`): `datetime()`'s default writes a space-separated, zone-less value that strict parsers (Rust `time`, GoToSocial/aoderelay relays) reject outright — `buildActor`, `buildNote` and `applyPollToNote` normalize every timestamp they emit.
- **Media downloads are named after the resource, never the bucket**: `mediaDownloadName` (`lib/media/filename.ts`) resolves description → the upload's own file name → the R2 key basename. R2 keys derived from `file.name` are sanitized (`safeUploadName`/`safeUploadExt`) on every upload route (media v1/v2, avatar/header).
- **Tabs**: every tab bar is `<Tabs>` from `components/Tabs.tsx` (sizing/font/state in the shared `.tab` class, `app/globals.css`, via `aria-selected`); never hand-roll one. `scroll` switches to auto-width tabs with horizontal overflow; otherwise tabs share the row equally.
- **Modals**: focus trap + focus restore via `useFocusTrap` (`components/useFocusTrap.ts`), used by EditStatusModal, Lightbox and LocationPickerModal.
- **Style**: no comments unless they explain *why*; TypeScript strict; `setX`/`handleX`/`fetchX` naming; admin pages keep the emoji prefix in nav/titles.

## Gotchas that have bitten before

- **`app/.well-known/**` is a dot-directory: TypeScript's `include` globs skip it.** A handler there compiles and ships with undefined references and only production finds out. `tsconfig.json` lists `app/.well-known/**/*.ts` explicitly **after** the generic globs — keep that line when the includes change. ESLint traverses it but `no-undef` is off for TS: lint is not a substitute for `tsc`. Guard: ESLint's `no-restricted-globals` rejects the DOM globals (`status`, `name`, `origin`, `top`, `event`, `window`, `navigator`…) in every server surface (`app/**/route.ts`, `src/**`, `proxy.ts`, `lib/**`), with client-side modules exempted one by one — a new file must be added deliberately.
- `wrangler.toml`'s `assets.directory` is the **build output** (`dist/client`). `vite build` emits `dist/client` + `dist/server` and writes `dist/server/wrangler.json` — the config `vinext-cloudflare deploy` actually ships; keep both in sync (`not_found_handling = "none"` keeps the worker answering every route).
- `proxy.ts` (Next.js 16's renamed middleware; vinext accepts `proxy` or `default` exports) only imports `next/server` — it runs inside the same Worker as the app. No matcher means it covers every dynamic route (static assets are served by Workers Assets first); matcher patterns must survive vinext's safety parser (no lookahead regexes). It also rejects non-multipart mutation bodies over 2 MB by declared `Content-Length`.
- `src/worker.ts` is wrangler's `main`: wraps the vinext handler (`vinext/server/fetch-handler`), exports the DO classes, and adds the queue consumer (incl. DLQ), the WebSocket upgrades (`/api/v1/streaming`, `/api/v1/calls/:id/ws`), the Guardian agent route and the cron. Intercept those **before** `handler.fetch`.
- **Never reference DOM globals in Workers code** (`status`, `name`, `origin`, `top`, `event`…): with `lib.dom` in tsconfig, `tsc` stays green but runtime throws `ReferenceError` — and a surrounding `try/catch` swallows it silently (a `status` typo made `broadcastObjectDelete` skip every list channel for months). Prefer `obj.visibility`, never bare `status`.
- **Ambient vs imported Cloudflare types drift**: `worker-configuration.d.ts` references the ambient globals while explicit `@cloudflare/workers-types` imports resolve to the package copy, and a types release made them structurally incompatible (`Headers.getAll`, generic `RequestInfo`). Shared helpers take **structural** parameters instead (`WaitUntilContext` in page-cache, the rate-limit namespace, `OrphanUploadBucket`) so they type-check in every tsconfig.
- `serializeAccount.url` is the **human profile** for a remote account (`https://domain/@user`) and `uri` the ActivityPub id (Mastodon semantics): the remote badge and "view original" must open `url` (the actor id answers JSON on most servers).
- The geolocated map (`LocationPreview`) is a tile mosaic **centred on the point**: the cover scale is driven by the **frame's** size and the pin-to-edge distances (`mapCoverScale`, `lib/location.ts`, unit-tested) — dividing by the mosaic's own (fixed) size always resolves to 1 and leaves white strips.
- Cron phases drift: `executeScheduled` aligns to the top of the minute; never assume `:00`. **The trigger's resolution is not the work's**: the cron fires every minute (a scheduled status must go out on time); throughput stages run every tick (bounded by their batch budgets); everything else declares its cadence with `schedule.every("<stage>", minutes)`. Current: **3 min** remote-poll refresh, expired-poll notifications, quote retries; **5 min** auto-delete, Guardian patrol, NodeInfo refresh, shared-inbox backfill, media-cache maintenance (the orphan scan itself stays hourly); **10 min** storage-retention deletes (its payload sample every 6 h), license icons, media backfill, media-reference repair, OAuth app cleanup; **15 min** account expiration, profile-field verification; **30 min** follow recommendations (own daily marker); **6 h** orphan-upload sweep. Stages with their own KV markers keep them. Adding a stage means picking an interval and saying why.
- `getFollow` does **not** filter by state — use `isAcceptedFollower` for followers-only visibility.
- Removing local accounts must clean `oauth_tokens`, `activities` and `moderation_log` (no FKs) and federate a `Delete` tombstone (`app/api/v1/accounts/delete/route.ts` and the admin DELETE route). `rejectAccount` cleans `oauth_tokens` too (actor ids are deterministic IRIs: a surviving token would resurrect for a re-registered username; `cleanup:orphan_oauth_tokens` heals old rows). `createPasswordReset` invalidates the actor's previous unused resets.
- Never re-ingest already-stored objects to change rendering — serializers read `objects.raw`, so rendering fixes are backward-compatible without migration.
- Web Push is silenced while a focused tab reports presence: the client heartbeats `POST /api/v1/push/presence` every 4 min (D1 `push_subscriptions.present_until`, 900 s TTL — D1, not KV, for strong consistency across colos) and `deliverPushNotification` skips while it is in the future. Beats that still leave more than half the horizon covered **skip the write** (the gate is in the UPDATE; multi-tab endpoints collapse into one cycle) and the blur/pagehide release writes only when a presence exists — one row per endpoint every ~8 min instead of every beat. A crashed tab resumes push within ~15 min. Do **not** skip `showNotification` in `public/sw.js` — Chrome substitutes "This site has been updated in the background" and burns the per-origin push budget.
- **Full-bleed pages must zero the mobile body paddings — never with negative margins** (they only move the palette band between edges). The pattern: inside the `max-width: 768px` block, `body:has(> main.graph-page), body:has(> .force-light) { padding-top: 0; padding-bottom: 0 }`. `.force-light` also sets **`color`** (inherited text otherwise keeps the dark-theme colour), and those pages' **viewport scrollbar** is repainted via ROOT pseudo-elements (`:root:has(.force-light)::-webkit-scrollbar-*`) — use the webkit pseudo-elements only (declaring `scrollbar-width`/`scrollbar-color` makes Chromium render the default thick bar). The landing footer is mobile-first (2-column links, copyright below) and restores the DOM order at `md:` with `md:order-none`.
